## 1. Executive Overview & Release Freeze Declaration

This document defines the formal integration contract for the DevMemory AI & Cross-Project Memory Engine (`ai_engine`). 

As of commit `930a961` on branch `feature/member-3-ai-memory`, all public function signatures, Pydantic schemas, retrieval interfaces, exception taxonomies, and privacy validation boundaries are **FROZEN**. Downstream consumers—specifically Member 1 (CLI Lead) and Member 2 (Backend & Database Lead)—must integrate against the interfaces specified herein.

### Strict Architecture Boundaries
- The AI Engine is an **offline-first, zero-untrusted-dependency Python module**.
- It does **not** expose HTTP endpoints, open server ports, or start background daemon threads.
- All integration occurs via direct Python function calls (`diagnose_error`, `retrieve_memory`) or via repository protocol implementations passed into the orchestrator.
- The engine enforces strict **fail-closed security**: client-supplied preference flags cannot bypass server-side authorization contexts, and all raw text returned by external providers is scrubbed for echoed secrets.

### 2.2 Input Schema: `DiagnosisRequest`

Defined in [`ai_engine.schemas`](file:///d:/projects/DevMemory/ai_engine/schemas.py). Configured with `extra="forbid"`: unexpected keys are rejected immediately.

```python
class DiagnosisRequest(BaseModel):
    model_config = ConfigDict(extra="forbid")

    event_id: str = Field(..., min_length=1, max_length=128)
    project_id: str = Field(..., min_length=1, max_length=128)
    command: str = Field(..., min_length=1, max_length=2000)
    exit_code: int = Field(...)
    error_message: str = Field(..., min_length=1, max_length=10000)
    stack_trace: Optional[str] = Field(default=None, max_length=50000)
    locations: List[SourceLocation] = Field(default_factory=list, max_length=50)
    source_snippets: List[SourceSnippet] = Field(default_factory=list, max_length=20)
    allow_cross_project: bool = Field(default=False)
```

#### Field Constraints and Validation Rules

1. `event_id` *(str, required, 1-128 chars)*: Unique UUID generated by runner or CLI.
2. `project_id` *(str, required, 1-128 chars)*: Identifier of the local active project.
3. `command` *(str, required, 1-2000 chars)*: Developer command executed (e.g., `npm run build`, `python main.py`).
4. `exit_code` *(int, required)*: Process exit status code (e.g., `1`, `137`, `101`).
5. `error_message` *(str, required, 1-10000 chars)*: Primary extracted error message or exception header.
6. `stack_trace` *(Optional[str], max 50000 chars)*: Full stack trace string.
7. `locations` *(List[SourceLocation], max 50 items)*: Structured code locations parsed from stack frames.
8. `source_snippets` *(List[SourceSnippet], max 20 items)*: Bounded source code lines surrounding error sites.
9. `allow_cross_project` *(bool, default=False)*: Client opt-in flag. **Note**: Cross-project precedents are only retrieved if both this flag is `True` **and** `auth_context.has_cross_project_read` is `True`.

class SourceSnippet(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid")

    file_path: str = Field(..., min_length=1, max_length=1000)
    start_line: int = Field(..., gt=0)

    @model_validator(mode="after")

        return self

### 3.2 Fix Status Lifecycle & Unverified Fix Guarantee

The lifecycle of recommendations is defined by `FixStatus`:

```python
class FixStatus(str, Enum):
    PROPOSED = "proposed"
    UNVERIFIED = "unverified"
    VERIFIED = "verified"
    FAILED = "failed"
```

#### The Unverified Fix Guarantee (Crucial Security Rule)
- An AI engine proposal is strictly **an unproven hypothesis until validated by test execution**.
- Even if an external LLM outputs `{"fix_status": "verified"}`, the orchestrator **unconditionally resets `fix_status` to `FixStatus.UNVERIFIED`** before returning to the caller.
- Only downstream execution harnesses that run verification commands and record pass/fail results may transition an incident's resolution to `FixVerificationStatus.VERIFIED`.

### 3.4 Provider Response Validation and Sanitization

When an LLM response is received, the engine enforces three stages of defensive post-processing:

1. **Markdown Fence Stripping**: Extracts valid JSON blocks from responses wrapped in ````json ... ````.
2. **Post-Processing Secret Redaction**: All strings across `summary`, `likely_cause`, `evidence`, `hypotheses`, `recommended_steps`, `uncertainty_description`, and `verification_steps` are re-sanitized through `redact_secrets` and `sanitize_file_path` to prevent echoed credential leakage.
3. **Parse Failure Handling**: If the LLM generates unparseable JSON, the engine catches the error and synthesizes a deterministic fallback response from Level 1 curated knowledge, guaranteeing no unhandled exceptions.

### 4.4 Matching Signals, Contradiction Guards & Taxonomy

1. **Exact Error Signature Matching**:
   - `compute_error_signature(msg, stack, cmd)` produces a deterministic SHA256 prefix `sig:<Type>:<hash>`.
   - Exact signature matches receive maximum similarity score (`max(0.98, lexical_score)`).

2. **Lexical Matching**:
   - Evaluates: Exception Type (0.35), Normalized Message (0.40), Stack Frames (0.15), Command Context (0.10).

3. **Hybrid Multi-Signal Fusion (`calculate_hybrid_score`)**:
   - Standard combination: `0.55 * lexical_score + 0.45 * vector_score + reliability_boost`.
   - `reliability_boost`: `+0.05` bonus if candidate resolution is verified (`FixVerificationStatus.VERIFIED`).

4. **Contradiction Guards & Taxonomy Calibration (`ai_engine.taxonomy`)**:
   - **Contradictory Exceptions** (e.g. `TypeError` vs `IndexError`): Capped to `score <= 0.35`. Semantic vector scores are discounted to prevent misleading correlations.
   - **Incompatible Tech Stacks** (e.g. Python vs Node.js): Score discounted by 25%.
   - **Compatible Subtypes** (e.g. `ModuleNotFoundError` -> `ImportError`): Recognized via static taxonomy; vector score received a calibrated 10% discount rather than a contradiction penalty.

### 4.5 Behavior Under Missing Matches or Provider Failures

- **Zero Matching Incidents**: Returns a valid `DiagnosisResponse` with `related_incidents = []` and general troubleshooting hypotheses synthesized from Level 1 curated knowledge.
- **Dense Vector Search Unavailable**: Falls back cleanly to exact signature and lexical token matching. No crashes or unhandled exceptions occur.

## 6. Security & Privacy Boundaries

### 6.1 Redaction Pipeline (`ai_engine.privacy`)

The AI engine automatically sanitizes all outbound payloads and incoming LLM text against six major secret categories:

1. **Private Keys & Certificates**: Multi-line PEM RSA, EC, and X.509 certificate blocks (`[REDACTED_PRIVATE_KEY]`, `[REDACTED_CERTIFICATE]`).
2. **API Keys & Tokens**: OpenAI (`sk-...`), Groq (`gsk_...`), GitHub (`ghp_...`), Slack (`xox...`), Stripe, SendGrid, and Bearer tokens (`[REDACTED_API_KEY]`, `[REDACTED_TOKEN]`).
3. **Database & Connection URIs**: Redacts embedded passwords in `postgres://`, `mongodb://`, `mysql://` URIs (`[REDACTED_URI_CREDENTIALS]`).
4. **Authentication Headers & Cookies**: Redacts `Cookie:`, `Authorization: Basic`, `X-Api-Key` headers (`[REDACTED_COOKIE]`, `[REDACTED_AUTH_HEADER]`).
5. **Machine & User Paths**: Obfuscates absolute home directories (`/Users/xyz`, `C:\Users\xyz`) into relative or neutralized `<home_dir>/...` formats.
6. **High-Risk File Exclusion**: Blocks source snippets from `.env`, `.pem`, `id_rsa`, `service-account.json`, and credentials files.

### 6.2 Prompt Injection Isolation
All user-provided commands, logs, and snippets are fenced within `=== OBSERVED DIAGNOSTIC EVIDENCE (UNTRUSTED DATA) ===` delimiters. Internal prompt instructions direct the LLM to treat this section strictly as inert diagnostic data.

1. Instantiate or implement `IncidentRepository` wrapping MongoDB queries for project and cross-project memory.
2. Construct `AuthorizationContext` based on verified session JWT/user authentication. Never trust client flags for `has_cross_project_read`.

3. Present `DiagnosisResponse.summary`, `likely_cause`, and `recommended_steps` to the developer.
4. Render `fix_status` clearly as **Unverified** until the user or test runner confirms resolution.
